# 处置手册

> 本文件由 `brain-checkup` skill 在需要时按需读取，不常驻上下文。
> 每一节对应一类症状，按诊断结果只读需要的那节即可。

### A. 目录页太长 → 下沉（≠ 压缩）

区别是一个可验证的数字：

| | 目录页 | 各笔记 | 合计 |
|---|---|---|---|
| ❌ 压缩（错误做法） | ↓ | 不变 | **↓ 内容真丢了** |
| ✅ 下沉（正确做法） | ↓ | ↑ | **不减** |

做法：目录页某行太长时 → 读对应笔记，**逐个要点核对是否已在其中**（语义核对，不是搜字符串）→
笔记里没有的**先补进去** → 目录行改写成「链接 + 关键词」。

🔴 **目录行必须留住"能撞上它"的关键词**：判据词、禁令词、专有名词、错误码、具体数值。
因为这类知识的特点是**「你不知道自己需要它」**——正要犯那个错时人不会想到查记忆，只能靠关键词命中。
写成「关于部署的经验」这种没钩子的描述，等于没写。

条数多时可派多个 subagent 并行核对，但**让它们只读、只返回结果，由你统一落盘**，避免同时写同一批文件。

### B. 有笔记没被收录 → 建二级目录

同一主题笔记超过约 15 条，主目录挂不下，就会退化成一串没有链接的词。
做法：建 `_index-<主题>.md` 分组列出（每条：链接 + 关键词），主目录留一行指过去。
⚠ 替换主目录整块前，**先看清这块里有没有本来就好的链接**，别把好的一起删了。

### C. 链接点过去是空的 → 修

最常见的不是文件没了，是**改名时分隔符变了**（目录写 `foo-bar`、文件叫 `foo_bar`）。
不是死链的两种情况：**指向另一个记忆库的**（跨库引用）、**模板占位写法**（`ep00XX-progress.md` 这类）。

### D. 笔记过期 → 先定环境归属，再谈淘汰

- 给笔记加三行标签：变化速度（年变/月变/周变）、状态、最后确认日期
- 「周变」类必须带一条可执行的验证命令，否则**说不准的易变事实是毒信息**
- 🔴 **淘汰前先过第 1 步的环境归属判定**：本机不成立 ≠ 过期
- ⚠ 批量加标签**会重置所有文件的修改时间**，之后判"多久没动"要读标签里的日期，不能看文件时间；
  加标签时日期写**改之前的文件时间**，不是当天
- 淘汰不是删除：搬到归档目录，但**必须配归档索引 + 主索引留一行带钩子的指针**（见 SKILL.md「归档 ≠ 移出可检索」）——
  只搬不留指针 = 慢性删除
- 拿不准时的安全动作：**加个"待核实"标记**，而不是删——删不可逆，标注可逆

### D2. 事实核验：能去实地验的，就别只标"待核实"

⚠ 这一节比 D 更进一步：D 只判断"这条属于哪台机"，**D2 是真的去那台机跑一遍，按结果改记忆**。

为什么必须做：记忆里写着端口、路径、版本、服务名这类**可以被验证**的事实，一旦过期，
AI 会**自信地按错的信息干活**——这比没有记忆更危险。而且它不会自己报错。

```bash
python3 <本 skill 目录>/scripts/verify-facts.py --base <记忆根> \
    [--discover]   # 额外列出「写了具体事实但没有验证方式」的文件
    [--remote]     # 允许跑含 ssh 的探针（会真的连出去，默认跳过）
```

工具只做两件事，**绝不自动改记忆**：跑已有的 `<!-- vrfy: 命令 -->` 探针；列出该配探针的文件。
它只跑只读命令（白名单 + 写操作关键词拦截），既不改记忆也不动被核验的系统。

#### 🔴 最重要的一条：探针失败**永远不能直接推出**"事实变了"

**证明"存在"只需要一次命中；证明"不存在"需要穷尽所有可能位置。**
一条 `test -d /some/path` 返回失败，只说明**那个路径上没有**，不说明那个东西不在了。

**拿到"不符"结果后，按这四类分诊**——不要一看失败就改记忆：

| 现象 | 真实原因 | 正确处置 |
|---|---|---|
| 本机失败，**去目标机跑成功** | 探针跑错机器 | 给探针标注执行环境，**记忆不用改** |
| 一个路径没有，**换个盘/目录就找到了** | **路径变了，东西还在** | 改探针路径，**记忆的事实部分不用改** |
| 本地找不到，**但线上/服务器在跑** | 载体换了位置，功能活着 | 探针改成查真正的运行位置 |
| **穷尽搜完都没有** | 事实可能真变了 | 才可以考虑改写记忆，且注明依据与日期 |
| 机器连不上 / 服务临时挂 | 环境问题，不是记忆问题 | **什么都别改**，记一笔下次再核 |

**穷尽清单（六条，缺一条就不许下"不存在"的结论）**

不要只记"要穷尽"这个原则——实践证明**原则拦不住第四次**。照着跑：

```bash
# ① 本机。是的，先查本机——哪怕探针写的是别的机器的路径
ls -d ~/projects/<名字> ~/<名字> 2>/dev/null; find ~ -maxdepth 3 -name '<名字>' 2>/dev/null

# ② 目标机的多个根目录，别只查记忆里写的那一个（盘符/工作根会变）
ssh <host> 'for r in <根1> <根2> <根3>; do find "$r" -maxdepth 3 -name "<名字>" 2>/dev/null; done'

# ③ 运行态而非文件位置——代码不在本地不代表服务没跑
ssh <server> 'systemctl list-units --state=running | grep -i <名字>; ss -tlnp | grep <端口>'

# ④ 有没有被【合并/改名/迁走】——查归档区与整理记录，别只查当前目录
grep -rl '<名字>' <归档目录> <整理记录/README> 2>/dev/null
```

⑤ **回头翻你自己在本轮里写下的结论**。整理过程会产出"某某已并入某某"这类判断，
   几十轮对话后你会忘掉它，然后把"合并"重新误判成"消失"。
⑥ **问用户**。一句话能省掉半小时穷举，而且他知道你查不到的搬迁史与合并史。

> **真实案例（同一个错四个变体，一次比一次基础）**：
> ① 在 Linux 主控机上把遥控 Windows 机所需的规则判成"过期残留" → 用户指出后实测，一条都不该删
> ② 改去目标机跑探针，仍有 5 条失败 → 判"项目早已迁走"
> ③ 用户指出后换盘搜，3 个项目躺在 `D:\work\projects\` 下，其中一个还在服务器上跑着
> ④ 用户再次指出：**本机 `~/projects/` 下也有**；另两个是**被合并进别的项目**了——
>    而"已合并"这个结论，是**我自己在同一轮整理的前几小时写进归档 README 的**，我忘了。
>
> 教训：**记忆整理者自己也会犯"知识写下来了但想不起来"的错**——这正是本 skill 要治的病。
> 所以判"不存在"必须走上面的清单，不能靠"我觉得我已经够谨慎了"。

> **真实案例（同一个错犯了三次，一次比一次隐蔽）**：
> 一次核验报出 7 条"事实不符"。
> 第一轮：全是 Windows 路径在 Linux 主控机上失败 → 以为都过期了。**错**，该去目标机跑。
> 第二轮：去目标机跑，1 条通过、5 条仍失败 → 判定那 5 条"项目早已迁走"。**又错**。
> 第三轮（用户指出后）：换几个盘搜，3 个项目好端端躺在 `D:\work\projects\` 下；
> 其中一个还在服务器上跑着（端口有进程在听）。**探针只查了记忆里写的那一个路径。**
> 教训：**每一轮我都以为自己已经够谨慎了**——防误判的规则要写成「穷尽标准」，不能只写「要小心」。

**配探针的原则**：
- 一条命令、只读、退出码有意义（`test -d`、`ls`、`curl -sI`、`systemctl status`）
- 探针要能反映**记忆里那个具体断言**，不是笼统探活
- 跨机的探针写成 `ssh <host> '<命令>'`，一眼看出该在哪跑
- 配不出探针的事实，说明它**本来就不该写成确定语气**——改成带条件的表述，或标注来源与日期

### E. 同一批内容有两套目录（换过机器/换过工具）

1. 先比对再动手：文件名差集 + 内容差集。⚠ 换行符差异（Windows/Unix）会制造"内容不同"的假象，先归一化
2. 确认哪边是全的，另一边整体**搬进归档**（是搬家不是删除）
3. 少数一边独有的内容，先合并过去再归档

### F. 怀疑以前压缩时压丢了东西 → 从版本历史找回

```bash
# 先探针：不在版本控制下就跳过本节（否则 git log 返回空且退出码 0，看起来像"没压缩过"）
git -C <记忆库根> rev-parse --show-toplevel
git -C <记忆库根> ls-files --error-unmatch <目录页路径>

git log --follow -- <目录页路径>       # 找压缩前后的提交
git show <压缩前提交>:<目录页路径>      # 取出旧版
```
把被删的句子拿到**当前全库**（各笔记 + 当前目录页 + 二级目录，三者缺一不可）查关键词命中率，
低命中的人工判断，确认全库都没有的从历史还原回对应笔记，并注明来源。

### G. 全新的库 → 直接建

- 目录页只放两种东西：① 当前在做的事（≤15 行，过期就降级）；② 稳定结论的索引（一行一条）
- 硬上限 **200 行 / 25KB，先到为准**。超出部分下次加载时读不到；写入时会有提醒/报错，不是完全无声
  （开头的标签行和注释不计入，此计法自 v2.1.211 起）
- 详细内容一律进各自的笔记
- 把记忆库放进 git（哪怕不推远端）——整理可回退，将来还能找回压丢的内容
