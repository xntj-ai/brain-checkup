# brain-checkup · 记忆体检

**不是给 AI 洗脑（brain-wash），是给它做体检（brain-checkup）。** 一个 Claude Code skill：给助手的长期记忆做体检，然后陪你把查出来的问题一项项修掉。

`v1.0.0` · [English](README.md)

洗脑是覆盖你的认知，体检是把结论交给你、你来拍板。这个区别就是整套设计：**原始笔记是证据层，永不被重写**；默认动作是**标注，不是处置**；每个判断点都回到你。

---

## 为什么需要它

长期记忆的腐坏是**不出声**的：

- **索引静默截断。** 超过加载上限，尾部直接不载入。不报错、不提示。你只会感觉助手"突然不记得了"。
- **越压越丢。** 一轮轮"整理"压的是**上一轮的产物**而不是原始材料，偏差按复利放大。有研究实测：反复自我摘要会让记忆效用**跌破"完全没有记忆"的基线**。
- **事实悄悄过期。** 端口、路径、版本、服务名 —— 写下来就再没人核过，然后被自信地用错。
- **你的检查器在骗你。** 这条最要命，见下。

## 最值钱的那个发现

第一次对真实记忆库（39 个库、1000+ 文件）全量跑下来，诊断**七次里错了六次**：

| 报告说 | 真相 | 量具错在哪 |
|---|---|---|
| 66 个孤儿笔记 | **10 个** | 只认 markdown 链接和 wikilink，而库里大量写成反引号文件名甚至裸词 |
| 38 条陈旧 | **0 条** | `last_verified` 是分层系统上线时**批量盖的戳**，之后没人更新 —— 它量的是盖戳日期不是陈旧度 |
| 7 处事实不符 | **0 处** | 探针写着 Windows 路径却在 Linux 上执行。**探针语法里根本没有"该在哪台机上验"这个位置** |
| 50 个文件消失 | **8 个** | 归档区在记忆库**之外**没被扫到，40 个只是搬了位置 |
| 5 条跨库引用"不是死链" | **5 条全是死链** | 唯一一次**漏报**：整座库被归档搬走后，指过去的相对路径全空，检查器却一律放行 |
| 19 项索引超标 | **1 项** | 18 项是"单行超 200 字符"—— 而盲测证明密集写法恰恰是**命中率最高**的 |

**天天误报的检查等于没有检查。** 照单全收去"修"，全是在给不存在的问题干活；而那唯一一次漏报，漏掉的是五条真死链。

所以本 skill 的第一条判据是：**先怀疑量具，再怀疑记忆。**

## 它到底做什么

对话式五步，每步之间都停下来等你：

1. **先了解你怎么干活**（不可跳过）—— 判任何东西"过期"之前，先定它**描述的是哪台机**。大多数"过期"只是在说另一台机器。
2. **体检** —— 只读扫描，动手前先存档，随时可一键回退
3. **用大白话汇报** —— findings 分三档：改了不影响你 / 会变但可回退 / 要你拿主意
4. **一项一项做**，边做边说
5. **盲测验收** —— 唯一能回答"到底有没有变好用"的一步

深度先定：**体检 / 轻整 / 深整 / 专项**。拿不准默认体检 —— 先诊断，再决定做到哪一档。

### 盲测抓到过一次退步

4 个互不知情的评估者、8 道来自真实历史事故的题、**只给索引不给正文**：

| | 命中 | 一跳内高信心 |
|---|---|---|
| 整理前 | 8/8 | **8** |
| 整理后（初版） | 8/8 | **7** ← 退步 |
| 修正后 | 8/8 | **8** —— 且索引小了 3.4 KB |

退步原因：下沉时把用户会去搜的**症状原话**（"封面候选都像同一个陌生人"）压成了技术名词 `FACE_BLOCK`。人是按症状搜的。**没有这一步，这个退步会被当成改善交付。**

## 安装

```bash
git clone https://github.com/xntj-ai/brain-checkup ~/.claude/skills/brain-checkup
```

然后对 Claude Code 说：**「给我的记忆做个体检」**。

脚本也可以单独跑：

```bash
python3 scripts/memory-gc.py      --base ~/.claude/projects        # 结构体检（只读）
python3 scripts/verify-facts.py   --base ~/.claude/projects        # 写死的事实还成立吗
python3 scripts/salvage-audit.py  --archive-root ~/你的归档目录     # 历次压缩到底丢了什么
python3 scripts/salvage-verify.py                                  # 逐条复核打捞候选
```

全部**只读**，没有任何脚本会改写记忆文件。

## ⚠️ 为 Claude Code 而写

本 skill 针对 Claude Code 的记忆体系编写，深度依赖它的具体形状：`~/.claude/projects/<桶>/memory/` 布局、由 cwd 派生的桶名（**首字符是 `-`**，是一大类工具坑的源头）、约 25600 字节的静默截断上限、`tier`/`status`/`last_verified` frontmatter、`<!-- vrfy: -->` 探针、`SessionStart` hook 协议。

**用别的智能体（Cursor / Codex / 自建）请 fork 后改造**：要换掉目录布局、上限数值、frontmatter 字段名、hook 契约。

**方法论部分是通用的**，而且是更值钱的那一半，可以直接搬：非对称举证（证有易证无难）· 先怀疑量具再怀疑记忆 · 判过期前先定环境归属 · 别在整理产物上再整理 · 归档≠移出可检索 · 盲测验收。
